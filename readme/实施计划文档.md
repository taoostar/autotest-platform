## 一、项目概述

本平台是一个企业级自动化测试平台，支持：
- 多用户多团队协作
- 测试用例在线管理与版本控制
- 分布式测试执行（Agent模式）
- 定时任务与Webhook触发
- 实时日志与性能监控
- 完整测试报告

**当前状态：** 后端API和前端页面基础框架已完成，需要完善Agent端和任务执行流程。

## 二、完整功能清单与实施计划

### 阶段一：Agent端实现（本机作为终端）

#### 步骤1：Agent核心模块

**目标：** 实现Agent客户端，能够注册到平台并接收任务

**文件结构：**
```
agent/
├── agent.py           # Agent主程序
├── executor.py        # 用例执行器
├── collector.py       # 性能数据采集
├── reporter.py        # 结果上报
├── requirements.txt
└── README.md
```

**功能点：**
| 功能 | 说明 | 优先级 |
|-----|------|-------|
| Agent注册 | 连接平台WebSocket，注册自身信息 | P0 |
| 心跳机制 | 每30秒发送心跳，维持在线状态 | P0 |
| 任务接收 | 接收平台下发的任务 | P0 |
| 任务执行 | 执行测试用例脚本 | P0 |
| 结果上报 | 上报执行结果到平台 | P0 |
| 性能采集 | 采集CPU/内存/IO/FD数据 | P1 |
| 日志推送 | 实时推送执行日志到平台 | P1 |
| 取消响应 | 响应平台取消任务指令 | P1 |

---

### 阶段二：任务执行流程

#### 步骤2：用例执行器

**目标：** 实现跨脚本类型的用例执行能力

**支持的脚本类型：**
| 类型 | 执行命令 | 依赖 |
|-----|---------|------|
| python | python {script} | pytest |
| shell | bash {script} | bash |
| javascript | node {script} | node |

---

#### 步骤3：性能数据采集

**目标：** 采集测试机性能数据

**采集项：**
| 指标 | 获取方式 | 说明 |
|-----|---------|------|
| CPU使用率 | psutil.cpu_percent() | 百分比 |
| 内存使用率 | psutil.virtual_memory().percent | 百分比 |
| IO等待 | psutil.disk_io_counters() | 差值计算 |
| 文件描述符 | len(psutil.Process().open_files()) | 数量 |

---

#### 步骤4：任务调度与分发

**目标：** 平台能够将任务分发到Agent执行

**任务状态机：**
```
pending → running → success
                  └→ failed
                  └→ cancelled
```

---

#### 步骤5：实时日志推送

**目标：** 前端实时显示任务执行日志

**实现方案：** Flask-SocketIO

---

### 阶段三：用例管理增强

#### 步骤6：Monaco编辑器集成

**目标：** 在前端实现完整的用例代码编辑功能

**功能点：**
| 功能 | 说明 |
|-----|------|
| 语法高亮 | Python/Shell/JavaScript |
| 自动补全 | 基础关键字补全 |
| 代码格式化 | 一键格式化代码 |
| 主题切换 | 浅色/深色主题 |
| 版本对比 | 两个版本diff对比 |

---

### 阶段四：报告与调度

#### 步骤7：报告导出功能

**目标：** 导出完整的HTML/PDF测试报告

**HTML报告内容：**
| 区块 | 说明 |
|-----|------|
| 摘要 | 总耗时、通过率，用例数量 |
| 用例列表 | 每个用例的状态、时间、错误信息 |
| 失败详情 | 错误类型、堆栈、截图 |
| 趋势图 | ECharts折线图 |
| 性能图 | CPU/内存图表 |

---

#### 步骤8：Cron调度器

**目标：** 实现定时任务的真正定时触发

**实现方案：** APScheduler + Redis
