# 性能报告集成需求分析

> **重要前置条件：** 必须先实现任务的串行/并行执行控制，只有串行执行时性能数据才有意义。

## 一、现状分析

### 1.1 当前 PerformanceCollector 采集的数据

**文件位置:** `agent/collector.py`

```python
# 当前采集内容
- cpu_percent: psutil.cpu_percent()           # CPU 使用率
- memory_percent: psutil.virtual_memory()      # 内存使用率
- io_read_mb / io_write_mb: psutil.disk_io_counters()  # 磁盘IO
- fd_count: len(process.open_files())         # 文件描述符(当前是全局的)
```

### 1.2 当前 PerformanceLog 模型

**文件位置:** `backend/app/models/task.py`

```python
class PerformanceLog(db.Model):
    cpu_percent: Float      # CPU 使用率
    memory_percent: Float   # 内存使用率
    io_wait: Float         # IO等待(当前无数据)
    fd_count: Integer      # 文件描述符(当前是全局的)
    # 缺少: load_average, process-specific 数据
```

### 1.3 当前问题

| 问题 | 说明 |
|------|------|
| 缺失 load_average | 系统负载数据未采集 |
| fd_count 不准确 | 采集的是 Agent 进程 open_files()，不是被测进程的 FD |
| 进程性能数据缺失 | 无法针对特定进程监控 |
| 数据与用例未关联 | PerformanceLog 是 task 级别，不是 case 级别 |
| 报告中未体现 | 前端 TaskDetail 未展示性能图表 |

## 二、需求详细分析

### 2.1 性能数据类型

#### 类型一：系统性能数据
| 指标 | 来源 | 说明 |
|------|------|------|
| cpu_percent | psutil.cpu_percent() | 系统 CPU 使用率 % |
| memory_percent | psutil.virtual_memory().percent | 系统内存使用率 % |
| load_average | os.getloadavg() | 系统负载 (1min/5min/15min) |

#### 类型二：进程性能数据（按关键字选择）
| 指标 | 来源 | 说明 |
|------|------|------|
| process_cpu | psutil.Process(pid).cpu_percent() | 进程 CPU 使用率 % |
| process_memory | psutil.Process(pid).memory_percent() | 进程内存使用率 % |
| process_fd_count | psutil.Process(pid).num_fds() | 进程文件描述符数量 |
| process_status | psutil.Process(pid).status() | 进程状态 |

**关键字匹配规则:**
- 匹配进程的命令行关键字（如 `python`, `node`, `java`, `pytest`）
- 如果匹配到多个进程，取 CPU 使用率最高的
- 如果无匹配进程，数据为空

### 2.2 数据关联设计

#### 方案A：PerformanceLog 关联 TaskResult（推荐）
```
TaskResult (case级别)
  └── PerformanceLog (多个，按时间序列)

优点: 天然与用例关联
缺点: 需要在用例开始/结束时清空/提交性能数据
```

#### 方案B：新增 ProcessPerformanceLog 表
```
TaskResult
  └── ProcessPerformanceLog (process级别性能)

优点: 数据结构清晰
缺点: 新增表和关联
```

**推荐方案A**，复用现有 PerformanceLog，新增字段区分系统/进程数据。

### 2.3 执行模式：串行 vs 并行

#### 现状问题
当前 `concurrency` 字段存在但**未实现真正的并发控制**：
- `dispatch_task()` 瞬间将所有用例发送给 Agent
- Agent 使用多线程并发执行，无法保证串行
- 性能数据在并发情况下不准确

#### 需求定义
| 模式 | concurrency | 行为 |
|------|-------------|------|
| 串行 | 1 | 一个用例执行完才开始下一个 |
| 并行 | >1 | 最多 N 个用例同时执行 |

#### 串行执行流程
```
dispatch_task():
  for case in cases:
    send task_assign to agent
    wait for task_complete signal  # 阻塞直到收到结果

# 或者 Agent 端控制：收到 task_assign 后等待上一个完成
```

#### 并行执行流程
```
dispatch_task():
  send all task_assign to agent (up to concurrency limit)
  Agent 执行: threading pool with max_workers=concurrency
```

#### 性能数据与执行模式关系
```
串行执行时:
  Case1: [====性能采集====]
  Case2:              [====性能采集====]
  Case3:                           [====性能采集====]

并行执行时 (不应采集):
  Case1: [====]
  Case2: [==]
  Case3: [====]
  (同时执行，进程资源竞争，性能数据无意义)
```

### 2.4 数据采集时机（串行模式）

```
用例执行流程:
┌──────────────────────────────────────────────────────┐
│ Start: TaskResult.started_at                         │
│   ↓                                                  │
│ 启动 PerformanceCollector                             │
│   ↓                                                  │
│ ┌──────────────────────────────────────────────┐     │
│ │ 采集循环 (每 5 秒)                             │     │
│ │  - 系统性能: cpu, memory, load               │     │
│ │  - 进程性能: 如果 process_keyword 存在        │     │
│ │    - 查找匹配的进程                          │     │
│ │    - 采集进程 CPU/内存/FD                    │     │
│ │  - 存储 PerformanceLog                       │     │
│ └──────────────────────────────────────────────┘     │
│   ↓                                                  │
│ 结束: TaskResult.finished_at                         │
│   ↓                                                  │
│ 停止 PerformanceCollector                             │
└──────────────────────────────────────────────────────┘
```

## 五、Agent 改动点

### 5.1 collector.py 改造

```python
class PerformanceCollector:
    def __init__(self, process_keyword=None):
        self.process_keyword = process_keyword  # 新增
        self.current_pid = None                  # 当前匹配的进程 PID

    def _find_target_process(self):
        """根据关键字查找目标进程"""
        if not self.process_keyword:
            return None

        for proc in psutil.process_iter(['pid', 'name', 'cmdline']):
            try:
                cmdline = ' '.join(proc.info['cmdline'] or [])
                if self.process_keyword in cmdline:
                    # 匹配成功，返回 CPU 最高的
                    return proc
            except:
                continue
        return None

    def _collect_loop(self):
        while self.running:
            # 系统性能
            cpu = psutil.cpu_percent()
            memory = psutil.virtual_memory().percent
            load_avg = os.getloadavg()

            # 进程性能
            process_data = None
            target = self._find_target_process()
            if target:
                try:
                    process_data = {
                        'keyword': self.process_keyword,
                        'pid': target.pid,
                        'cpu': target.cpu_percent(),
                        'memory': target.memory_percent(),
                        'fd_count': target.num_fds(),
                        'status': target.status()
                    }
                except:
                    pass

            # 发送数据
            self.send_callback(self.task_id, {
                'system': {
                    'cpu': cpu,
                    'memory': memory,
                    'load_avg': list(load_avg)
                },
                'process': process_data
            }, self.result_id)  # 传递 result_id

            time.sleep(self.interval)
```

## 八、风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| 性能采集影响执行性能 | 使用独立线程，采样间隔可配置（默认 5s） |
| 进程关键字匹配不准 | 匹配多个时取 CPU 最高的，无匹配时数据为空 |
| 数据量膨胀 | TaskResult 存汇总，PerformanceLog 可按需清理 |
| 前端图表渲染慢 | 分页加载 + 懒加载 |
