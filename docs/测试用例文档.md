### 1.2 串行执行验证

#### TC-EXEC-010: 串行执行用例顺序验证
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-EXEC-010 |
| **用例名称** | 串行执行用例顺序验证 |
| **前置条件** | 1. 存在包含 3 个用例的计划 Plan-Test<br>2. Plan-Test 下所有用例执行时间 > 2 秒<br>3. 存在在线 Agent |
| **测试步骤** | 1. 创建任务 Task-001，选择串行执行<br>2. 分发任务 Task-001<br>3. 立即观察任务详情页的用例执行状态 |
| **预期结果** | 1. 同一时刻最多只有 1 个用例处于 running 状态<br>2. Case2 在 Case1 完全完成后才开始执行<br>3. Case3 在 Case2 完全完成后才开始执行<br>4. 用例执行顺序与计划中的 order_index 一致 |

#### TC-EXEC-011: 串行执行性能数据隔离
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-EXEC-011 |
| **用例名称** | 串行执行性能数据隔离 |
| **前置条件** | 1. 计划包含多个用例<br>2. 配置了性能采集 |
| **测试步骤** | 1. 创建串行任务并分发<br>2. 等待所有用例完成<br>3. 查看每个用例的性能数据 |
| **预期结果** | 1. Case1 的 performance_logs 时间范围: Case1.start → Case1.end<br>2. Case2 的 performance_logs 时间范围: Case2.start → Case2.end<br>3. 两个用例的性能数据时间不重叠 |

#### TC-EXEC-012: 串行执行用例失败不影响后续用例
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-EXEC-012 |
| **用例名称** | 串行执行用例失败不影响后续用例 |
| **前置条件** | 1. 计划包含 3 个用例: Case1(失败), Case2(成功), Case3(成功)<br>2. 串行执行模式 |
| **测试步骤** | 1. 创建并分发串行任务<br>2. 观察 Case1 失败后任务是否继续 |
| **预期结果** | 1. Case1 失败后，Case2 仍然开始执行<br>2. Case3 在 Case2 完成后执行<br>3. 最终任务状态为 failed（部分成功） |

## 二、性能数据采集测试用例

### 2.1 系统性能采集

#### TC-PERF-001: 系统性能数据采集完整性
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-PERF-001 |
| **用例名称** | 系统性能数据采集完整性 |
| **前置条件** | 1. Agent 已安装 psutil<br>2. 任务配置为串行执行 |
| **测试步骤** | 1. 创建任务并分发<br>2. 等待任务完成<br>3. 查询 performance_logs 表 |
| **预期结果** | 每条性能记录包含:<br>- cpu_percent: 0-100 数值<br>- memory_percent: 0-100 数值<br>- load_avg_1: >= 0 数值<br>- load_avg_5: >= 0 数值<br>- load_avg_15: >= 0 数值 |

#### TC-PERF-002: 性能采样频率验证
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-PERF-002 |
| **用例名称** | 性能采样频率验证 |
| **前置条件** | 串行任务执行时间约 30 秒 |
| **测试步骤** | 1. 创建并分发串行任务<br>2. 查询 performance_logs 记录数<br>3. 计算实际采样间隔 |
| **预期结果** | 1. 记录数 ≈ 执行时间 / 5秒<br>2. 间隔误差在 ±1 秒内 |

#### TC-PERF-003: 用例执行期间性能数据连续性
| 属性 | 值 |
|------|-----|
| **用例ID** | TC-PERF-003 |
| **用例名称** | 用例执行期间性能数据连续性 |
| **前置条件** | 串行执行任务 |
| **测试步骤** | 1. 查看任意用例的性能数据<br>2. 检查 timestamp 连续性 |
| **预期结果** | 1. 第一个采样时间 >= case.started_at<br>2. 最后一个采样时间 <= case.finished_at<br>3. 相邻采样时间差约为 5 秒 |
